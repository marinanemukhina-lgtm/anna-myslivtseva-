# Анна Мысливцева — сайт и панель управления

Самостоятельный русскоязычный сайт на React с серверной панелью управления. Визуальный ориентир — [Odyssee Clinic](https://www.odysseeclinic.com.au/): композиция, сетка, спокойная типографика, полноэкранные медиа, раскрывающееся меню, смена слайдов и движение элементов при прокрутке.

Использованы предоставленные фотография Анны и два видео. Неизвестные сведения оставлены пустыми. В проекте нет выдуманных услуг, медицинских квалификаций, результатов лечения, цен или контактов.

## Доработанная версия

Крупный двухстрочный титул, контрастная постоянная навигация, локальные Cormorant Garamond и Inter, редакционные блоки, отдельная страница `/diplomas` с прямым входом с первого экрана. На главной сохранены большие видео, слайдер и длинная последовательность разделов; добавлены отдельный блок образования и ссылки на новости/акции.

На первом экране — живой портрет с улыбкой, замедленный в 2,2 раза; доступна остановка движения. Видео массажа приведены к нейтральной палитре. Полная замена интерьера пока не выполнена. Дипломы не выдуманы: раздел ждёт загрузки реальных файлов.

Фото и видео хранятся в репозитории частями в `.media-parts`. Перед запуском и сборкой `scripts/restore-media.mjs` автоматически восстанавливает исходные файлы и проверяет SHA-256. Качество медиа не меняется; дополнительные загрузки из внешних сервисов не нужны.

## Быстрый запуск

Нужен Node.js 22.13 или новее; для разработки и CI рекомендуется Node.js 24.

```sh
npm ci
npm run setup
npm run dev
```

Откройте `http://localhost:4173`. Панель: `http://localhost:4173/admin`.

Команда `setup` попросит придумать пароль длиной от 12 символов. Ввод скрыт; в `.env` сохраняется только хеш. Общего пароля по умолчанию нет. Если настройка пропущена, сайт работает, а вход в панель недоступен.

### Настройка пароля с телефона или планшета

На уже размещённом сайте откройте `/admin/setup`. Страница вычисляет хеш только в браузере: введите и повторите свой пароль, нажмите «Сформировать хеш», затем вручную скопируйте результат в переменную `ADMIN_PASSWORD_HASH` нужного окружения проекта Vercel и выполните новое развёртывание. Никакие настройки сайта страница сама не меняет.

Для входа в панель на Vercel также требуется настроенное подключение `DATABASE_URL`. Один хеш пароля не подключает базу данных. Локальная версия по-прежнему может работать с SQLite без этой переменной.

Не отправляйте пароль, хеш или строку подключения в чат, не добавляйте их в код, репозиторий или снимки экрана. Вводите и сохраняйте их самостоятельно на доверенном устройстве. Кнопка «Очистить» убирает значения со страницы, но не очищает буфер обмена и не гарантирует удаление из памяти браузера.

Для локальной работы не нужен внешний сервис: изменения и загруженные файлы хранятся в `.data/content.sqlite`. После перезапуска они сохраняются. `.data` и `.env` не входят в Git. Для резервного копирования локальной версии остановите сервер и скопируйте весь каталог `.data` в защищённое место.

Собранная версия:

```sh
npm run build
npm start
```

## Что редактируется в панели

| Раздел        | Возможности                                                                                                                                  |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| О себе и сайт | Имя, специализация, тексты главной страницы, биография, квалификация, фото и положение кадра, контакты, часы приёма, ссылки, документы сайта |
| Услуги и цены | Название массажа или другой услуги, описание, стоимость, длительность, категория, фотография                                                 |
| Новости       | Заголовок, дата, текст, фотография                                                                                                           |
| Акции         | Предложение, цена, срок, условия, фотография                                                                                                 |
| Дипломы       | Название, учебное заведение, год, описание, изображение или PDF                                                                              |

У записей есть черновик, публикация, изменение порядка и удаление. Сначала внесите изменения, затем нажмите «Сохранить». Галочка «Показывать на сайте после сохранения» определяет видимость записи. Дата новости — подпись, а не отложенная публикация. Срок акции отображается посетителю; снять завершившуюся акцию можно той же галочкой.

Файлы: JPG, PNG, WebP, для дипломов также PDF; до 3 МБ на файл. Встроенные видео находятся в `public/media/` и заменяются при обновлении исходников. Панель рассчитана на одного владельца, без регистрации посетителей и сбора медицинских данных.

Чтобы заменить главное фото: «О себе и сайт» → «Главная фотография» → «Заменить файл» → «Сохранить изменения». Параметр положения кадра позволяет настроить обрезку. Исходная фотография включена в проект.

## Vercel

Проект включает `vercel.json` и серверную точку входа `api/index.mjs`.

1. Импортируйте GitHub-репозиторий в Vercel. Корень проекта — эта папка, Framework Preset — **Other**, Build Command — `npm run build`, Output Directory — `dist/client`. Выберите Node.js 24.
2. Подключите Neon Postgres. В переменную `DATABASE_URL` добавьте строку подключения Neon. Сервер использует HTTP-драйвер Neon; произвольный обычный PostgreSQL-сервер без этого интерфейса не подходит.
3. Локально выполните `npm run setup`. Скопируйте значение `ADMIN_PASSWORD_HASH` из `.env` в одноимённую переменную окружения Vercel. Сам пароль в GitHub или Vercel добавлять не нужно.
4. Добавьте обе переменные для нужного окружения. Для Preview используйте отдельную базу или ветку Neon, чтобы проверка не меняла рабочий сайт.
5. Выполните Deploy. Таблицы создаются при первом обращении к API. Откройте `/admin`, войдите, внесите реальные сведения и сохраните.

Без `DATABASE_URL` на Vercel доступна исходная публичная версия сайта, а панель сообщает, что настройка не завершена. Без хеша пароля вход закрыт. Локальные данные SQLite не переносятся в Neon автоматически: при первом размещении база содержит только исходное имя, фотографию и пустые разделы.

Тексты, сессии и загруженные изображения/PDF хранятся в Postgres, поэтому сохраняются между вызовами Vercel Functions и повторными размещениями. Видео из исходников обслуживаются как статические файлы. Резервное копирование рабочей базы настраивается в Neon.

После размещения проверьте вход и выход, создание черновика, публикацию, загрузку диплома, открытие прямой ссылки на новость и отображение на телефоне. Облачная база и реальное размещение требуют подключения ваших учётных записей; в этой поставке проверен локальный сервер с SQLite, сборка и браузерные сценарии.

Официальные справки: [Vercel Functions](https://vercel.com/docs/functions/runtimes/node-js), [маршрутизация Vercel](https://vercel.com/docs/routing/rewrites), [Neon serverless driver](https://neon.com/docs/serverless/serverless-driver).

## Страницы и поведение

Главная, услуги и цены, об Анне, новости, отдельная новость, акции, отдельная акция, дипломы с просмотром, контакты, конфиденциальность, условия использования, панель администратора.

Меню закрывается по Escape и клику на фон, удерживает фокус и возвращает его на кнопку открытия. Слайдер поддерживает нажатия, автоматическую смену, свайп и паузу при наведении/фокусе. Видео воспроизводятся без звука в видимой области. Учтена настройка уменьшения движения; в подвале есть ручной переключатель анимации. На компьютере список из 2–6 услуг меняет активный пункт при прокрутке и по нажатию; более длинный список, мобильная версия и режим без анимации используют раскрытие по нажатию.

## Контакты и эксплуатационные ограничения

Контактный диалог использует опубликованные телефон и SMS-ссылки. Обратный звонок не бронирует время, не обещает срок ответа и не отправляет автоматические уведомления. Сохранённые обращения доступны только в защищённом списке владельца; временный открытый редактор не получает к ним доступ. Новые поля `officeAddress`, `directionsUrl` и `heroPortrait` не заменяют существующие данные профиля.

### Проверки перед выпуском

Используйте Node.js >=22.13 (CI: Node.js 24), зависимости из `package-lock.json` и `npm ci`. `npm run build` восстанавливает упакованные медиа и создаёт `dist/client/index.html`, `dist/server/index.js`, `dist/.openai/hosting.json`.

- `npm run test:contact:local` — последовательные синтетические unit-тесты, сборка, Sites и compiled-worker проверки с очищенным процессным окружением. Требует уже установленные зависимости и отказывается работать рядом с runtime `.env` файлами.
- `npm run test:contact:ui` — unit/SSR проверки контактного интерфейса.
- `npm run test:postgres:tls` — TLS в памяти; не заменяет настоящий PostgreSQL.
- `npm run test:editorial:browser` и `npm run test:contact:browser` — браузерные сценарии. Discovery не означает прохождение тестов.
- `node scripts/run-contact-checks.mjs pg16` — заранее созданные одноразовые loopback fixtures на 55432/55433 из соответствующих workflows.
- `node scripts/run-contact-checks.mjs pg18 /path/to/fixture-server.crt` — заранее созданный одноразовый PostgreSQL 18/TLS fixture на 55434. Файл — публичный сертификат тестового сервера.

Тестовые подключения и пароли в workflows предназначены только для одноразовых синтетических баз. Не использовать их в рабочем окружении и не подставлять production URL в тесты. PostgreSQL-тесты без соответствующих fixtures пропускаются; skip не подтверждает работоспособность БД. Проверять точную выпускаемую ревизию. Ветка `prep/anna-complete-contact-20261108` имеет `git.deploymentEnabled: false`; этот запрет автоматической публикации сохраняется.

### Обратный звонок выключен по умолчанию

Для включения необходимы защищённый доступ владельца, постоянное хранилище, закрытый публичный редактор и оба флага `CONTACT_CALLBACK_ENABLED=true`, `CONTACT_CALLBACK_DATA_APPROVED=true`. Также нужны опубликованные полные политика `/privacy` и отдельный документ `/callback-consent`: версия, имя и реквизиты оператора, текст. `CONTACT_CALLBACK_RELEASE_VERSION` должен совпадать с SHA-256 точных документов, вычисляемым `callbackReleaseRevision(profile)` из `shared/callbacks.mjs`. Изменение политики, версии, оператора или текста закрывает приём до обновления значения. Секреты и настоящие документы не выводить в журналы для расчёта хеша.

Неполные документы, отсутствующее или устаревшее значение оставляют приём закрытым. Сохранение черновика не включает форму. Непустые строки и checkbox не устанавливают юридическую достаточность: до выпуска требуется проверить реальные документы, оператора, весь путь обработки, доступы, обработку отзыва, резервные копии и срок хранения.

Успех возвращается после фиксации записи. Повтор неопределённой отправки должен сохранять прежний requestId. Точные снимки согласия сохраняются отдельно; старые plaintext-снимки остаются читаемыми. Очистка обращений старше 30 дней выполняется при доступе к сервису, не по расписанию, и не удаляет резервные копии. Снимки согласия автоматически не удаляются. Это не гарантия срока удаления; нужен проверенный эксплуатационный порядок.

### Прямой PostgreSQL и сохранность данных

Без `DATABASE_DRIVER` сохраняется прежний выбор: `DATABASE_URL` включает Neon, отсутствие URL вне Vercel — локальный SQLite. `DATABASE_DRIVER=postgres` включает прямой `pg`: URL со схемой postgres/postgresql, пользователем, паролем и именем БД, без query-параметров и fragment. Неверная явная конфигурация не переключается на другую БД. `DATABASE_TLS_CA_PEM` задаёт публичную CA-цепочку, иначе используются системные CA. Проверка сертификата/имени и TLS >=1.2 обязательны; отключать проверку нельзя. Пул ограничен четырьмя соединениями на процесс. Startup создаёт таблицы и требует соответствующих прав; DML-only роль пока недостаточна.

Размещение БД в России само по себе не локализует API, CDN, журналы, резервные копии и остальные получатели данных. Перед сменой хранилища нужен отдельный проверенный план полного переноса, единого согласованного снимка, сверки и отката. Не запускать приложение на пустом target до восстановления. Не удалять исходную БД и не менять origin без сохранения доступа к данным.

`pg_dump` не переносит статические медиа и браузерные истории/фото, локальные маркетинговые черновики, cookies и незавершённые формы. Карточки демонстрационного раздела привязаны к localStorage текущего origin. Обычный JSON сохраняет текущее состояние вкладки, ZIP — выбранную карту. Для исходной записи v1 или некорректной записи нужна отдельная raw-копия. Импорт ZIP добавляет карту и посещения только без конфликтов идентификаторов и не заменяет существующую коллекцию. Общего импорта произвольного JSON через UI нет; восстановление canonical raw-копии допускается только в отсутствующий ключ хранилища. Не очищать старый origin. Локальные маркетинговые черновики требуют отдельного сохранения до загрузки серверной версии. Существующие тексты, услуги, специализацию, фото, дипломы и карточки нельзя заменять начальным набором. Открытый демонстрационный раздел не предназначен для реальных медицинских данных.

## Ограничения защиты локальных историй

Проверки выполняются только на синтетических данных. Реальные записи и восстановление пользовательских данных не проверены. Старые незакрытые вкладки не участвуют в новом протоколе Web Locks: перед работой с новой версией их необходимо закрыть. Исходная строка в памяти вкладки не является резервной копией. Восстановление исходной копии допускается только при отсутствующем ключе хранилища; существующее значение не перезаписывается. Эти меры не заменяют отдельную проверку сохранности существующего хранилища перед публикацией.
