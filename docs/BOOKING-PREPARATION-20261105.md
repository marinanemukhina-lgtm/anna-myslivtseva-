# Закрытая подготовка записи

Эта ветка подготовлена отдельно от опубликованного сайта. Она **не включает публичную запись** и не содержит реальных расписаний, имён, контактов или заметок пациентов.

## Что реализовано

- Настройки рабочих часов, отдельных дат, часового пояса, длительности услуг, перерывов, горизонта и минимального времени до приёма сохранены.
- Защищённое управление обезличенными занятыми интервалами, внутренними резервами и отменой. Все новые `/api/admin/booking/*` маршруты требуют настоящую сессию администратора. Временный открытый контентный редактор её не заменяет.
- Настройки, занятость и весь контент используют одну строку и одну версию хранилища. Атомарный compare-and-swap предотвращает потерю изменений, пересекающиеся бронирования и гонку с изменением настроек. Уникальности начала приёма недостаточно, поэтому проверяется весь интервал вместе с перерывом.
- Повтор операции использует прежний ключ и не создаёт вторую запись. При неизвестном результате интерфейс требует обновить данные. Повтор не воскрешает отменённую запись.
- Свободные слоты выдаются только для опубликованной включённой услуги и свежего явно сверенного периода. Неподтверждённый, неполный или просроченный источник не означает пустой календарь. Подтверждение занятости действует не более 24 часов. Показанный расчёт помечен временем проверки и истекает не позднее минуты, конца подтверждения или начала ближайшего слота; перед выбором его нужно обновить.
- Предварительный просмотр импорта принимает только начало/конец интервалов и SHA256 исходника. Применение требует явного подтверждения, того же содержимого и версии. Исходные файлы, имена, заметки, контакты и сведения о здоровье API не принимает.
- Контентный редактор и публичный API не показывают занятость. Сохранение контента сохраняет частные поля и проверяет точную исходную версию. Логи ошибок не содержат текст запроса.
- Ответ атомарной операции отделён от последующего чтения: чтение после чужого изменения не обновляет версию несохранённого черновика редактора.

## Интерфейс и маршруты

В защищённом календаре есть добавление занятости, отмена, просмотр списка и подтверждение проверенного периода. Для времени в новой панели пока используется явный ISO UTC с `Z`, без автоматического выбора часового пояса устройства.

- `GET /api/admin/booking/occupancy`: частное состояние и версия.
- `GET /api/admin/booking/free-availability`: окна с учётом занятости и перерывов; это предварительный результат, не бронь.
- `PUT /api/admin/booking/coverage`: подтверждение периода и срока актуальности.
- `POST /api/admin/booking/busy`: обезличенные занятые интервалы.
- `POST /api/admin/booking/reservations`: внутренний резерв, не подтверждённая запись пациента.
- `POST /api/admin/booking/records/:id/cancel`: отмена с проверкой версии.
- `POST /api/admin/booking/import/preview` и `/apply`: проверка и подтверждаемое применение нормализованных интервалов.

Публичный `/api/booking/appointments` по-прежнему возвращает 503 до разбора тела запроса. `/api/booking/config` возвращает `ready:false`, `enabled:false`; публичная выдача слотов пуста. Настройка часов или подтверждение периода не снимает эту блокировку.

## Локальная проверка экспорта

Оба инструмента читают исходник, не изменяют его, не отправляют данные в сеть и не выполняют импорт. Не добавляйте исходные файлы и результаты с реальными интервалами в репозиторий.

### ICS

`node scripts/preview-booking-ics.mjs LOCAL_FILE [--timezone TIMEZONE]`

Поддерживается строгий ограниченный набор VEVENT с DTSTART/DTEND. Поля идентификации отбрасываются. События консервативно трактуются как занятые интервалы. Поддерживаются UTC, фиксированные Etc/GMT и явно заданный современный Europe/Moscow в 2015–2030. Повторяющиеся события, пользовательские зоны и неоднозначные неподдерживаемые варианты отклоняются целиком, а не частично. Успешный разбор не доказывает полноту или актуальность.

### Shifter

`python3 scripts/preview-shifter.py LOCAL_FILE`

Проверяется ограниченная изученная схема SQLite. Файл открывается только для чтения через уже открытый дескриптор, `immutable=1`, `query_only=ON`, `trusted_schema=OFF`. Проверяются SHA256 и неизменность байтов, размеры, строки, sidecar-файлы, схемы и типы. Views, triggers, virtual tables, неизвестные корректировки времени и неподдерживаемые настройки отклоняются.

**Дата `fecha` кодируется с нулевым месяцем:** `year = fecha // 10000`, `month = (fecha // 100) % 100 + 1`, `day = fecha % 100`. Все даты валидируются. Версия результата `shifter-shift-preview-v2`, `dateEncoding: year-month0-day`. Обычный YYYYMMDD-декодер применять нельзя.

Результат содержит только локальные сегменты смен и маркеры, без заметок и названий. Часовой пояс остаётся неизвестным; равные границы не становятся 24-часовым событием, ночные и разделённые смены требуют проверки. Отсутствующие даты не заполняются. Смены сами по себе не доказывают точные интервалы приёмов: записи могут быть в заметках, которые инструмент намеренно не читает. Требуются Linux `/proc` и SQLite с `table_list`.

Официальное приложение: https://play.google.com/store/apps/details?id=com.lrhsoft.shiftercalendar . Официальный сайт: https://www.lrhsoft.com/wsc.html . .Shifter не считается публично документированным стандартом. Разовый экспорт не является синхронизацией.

## Проверки и границы готовности

`npm test`, `npm run test:sites`, `npm run build` включают новые тесты менеджера, HTTP-защиты, приватности, ICS и Shifter. Гонки проверяются двумя независимыми подключениями SQLite на синтетических данных. Отдельные сценарии браузера добавлены, но в текущем окружении не выполнены: установленный браузер блокируется ограничениями запуска, а облачный браузер не видит локальный тестовый сервер. Проверки PostgreSQL/Neon и реального входа владельца тоже ещё требуются.

Ранние изолированные модули `shared/booking-busy.mjs` и `server/anonymous-booking-store.mjs` оставлены с тестами как прототипы. Второй **не подключён** к маршрутам и не заменяет интегрированный `server/private-booking-state.mjs`.

## Перед включением настоящей записи

1. Подтвердить часовой пояс, рабочие окна, длительности, перерывы и точное значение экспортированных записей. Не объявлять пустые даты свободными.
2. Сверить только обезличенные интервалы со свежим источником. Не переносить произвольные заметки. Определить обновление новых записей, сделанных вне сайта.
3. Завершить закрытый доступ владельца, устойчивое защищённое хранилище, проверку восстановления и сроков хранения. Открытый контентный редактор не подходит для управления пациентскими данными.
4. Определить минимальные контактные данные, уведомления, согласия, отмену и подтверждение для реального клиента. Сейчас эти функции не реализованы и данные клиентов не принимаются.
5. Пройти браузерные и серверные проверки на целевом защищённом окружении. Снимать публичную блокировку только отдельным проверенным изменением.

## Изолированная проверка PostgreSQL и браузера

Для draft-ветки `prep/anonymous-busy-windows-20261105` в `vercel.json` запрещён автоматический деплой; остальные ветки не меняются. Основание: https://vercel.com/docs/project-configuration/git-configuration . GitHub Actions может проверить код без публикации приложения и без подключения рабочего хранилища.

Отдельный workflow `booking-postgres.yml` использует временный PostgreSQL 16 и только синтетическую базу. Тест не читает `DATABASE_URL`, требует явного режима `synthetic-only` и loopback-адреса. Без настройки он явно пропускается; при неверной настройке или отсутствии psql падает. Локально PostgreSQL, psql и Docker недоступны, поэтому проверка реального PostgreSQL пока не выполнена.

Существующий браузерный workflow запускает изолированный QA-сервер и вымышленные данные. До выпуска нужны успешные результаты обоих workflow на точном финальном коммите. Создание draft-ветки/PR не означает разрешение на слияние или включение публичной записи.
