Переносимый приём: собрать карту реальных вопросов аудитории, затем под каждый тип запроса создавать обоснованные страницы и проверять индексацию. Не публиковать 25 пустых или выдуманных страниц ради количества.

## Что изменено в коде

- Раздельные заголовки и описания основных страниц; обновление canonical при клиентской навигации.
- Разметка Person по уже существующим публичным полям: имя, роль, URL; без медицинской лицензии, рейтинга или отзывов.
- noindex, nofollow для административных, демонстрационных, непубликуемых и неизвестных страниц.
- robots.txt: закрыть /admin, /demo и техническое /api, разрешив адрес служебной карты.
- GET /api/seo/sitemap.xml: только фактически опубликованные страницы/новости/акции. Требуется точный PUBLIC_SITE_URL (HTTPS); домен не угадывается из Host.
- Тесты tests/seo.test.mjs без реальных клиентов.

Яндекс документирует исполнение JavaScript на AJAX-сайтах, но для проверки фактического индексирования нужен Яндекс Вебмастер и тест «Рендеринг JavaScript». У текущего React SPA есть дополнительная зона риска: сервер возвращает общее HTML для маршрутов; отдельный SSR/SSG-проход может понадобиться по результатам реального обхода.

## Перед реальным запуском SEO

1. Подтвердить канонический домен и задать PUBLIC_SITE_URL=https://домен/ в окружении; это настройка, не секрет.
2. Опубликовать подтверждённые контакты и сведения об услугах через существующую панель Анны.
3. Зарегистрировать /api/seo/sitemap.xml в Яндекс Вебмастере после фактического выпуска; проверить HTTP 200, robots.txt, JS-рендеринг и статус страниц.
4. Не включать синтетическую запись в индекс и не создавать публичные реальные медицинские карты.
5. Отдельно проверить доступность пустых/несуществующих страниц: текущее SPA может отдавать HTML со статусом 200, что Яндекс относит к ошибке качества индексации.

Никаких гарантий попадания в ТОП, сроков индексации или роста обращений данный прототип не даёт.
