## Статус

Подготовлен и исполнен серверный сценарий с реальными HTTP-запросами к временному локальному серверу. Данные полностью синтетические. Состояние нового демо — только в памяти; рабочая БД и переменные подключения не используются. Два теста старых ограничений используют SQLite `:memory:`. Существующая регрессия использует собственные временные синтетические SQLite-фикстуры.

Публичная запись закрыта. `server/app.mjs`, `server/booking.mjs`, `server/private-booking-state.mjs`, производственная схема и маршруты не изменены. Демо не импортируется из основного приложения, Vercel API или worker. Обычная сборка не включает `booking-demo.html`. Новый интерфейс собирается отдельно в `.qa/demo-dist`.

Не выполнены: push, создание PR, слияние, развёртывание, миграция, настройка рабочего окружения, реальная запись, отправка сообщений. Медицинские карты, визиты, фотографии и экспорт PR5 не подключались.

## Контракт демонстрации

- Часы условные: 6 ноября 2026, 09:00 МСК плюс время работы демо. Приём 7 ноября, 09:00–17:00 МСК, две явно тестовые услуги 60/30 минут, перерыв 15 минут. Это не расписание Анны.
- Источник `fresh`: явно заданная тестовая сверка; `stale`: срок истёк; `incomplete`: сверки нет. Неизвестные интервалы никогда не добавляются как свободные.
- Клиент выбирает одну из трёх вымышленных персон. Строгая схема отвергает телефон, email, заметки и любые лишние поля.
- Выдача времени действует не более минуты. Сервер перед резервом заново проверяет версию, услугу, дату, время, занятость, буфер и покрытие.
- pending удерживает интервал. Пять минут — демонстрационное допущение, не утверждённая политика владельца. Истечение обрабатывается перед следующей операцией/чтением; фонового таймера нет.
- Подтверждение повторно проверяет актуальность, услугу, длительность, буфер, срок резерва и общую версию. Оно не удостоверяет личность клиента и не отправляет уведомления.
- cancelled/expired нельзя подтвердить или воскресить старым ключом. Новый выбор требует новой операции.
- Один ключ с тем же содержимым возвращает прежнюю запись. Изменённые данные либо чужая сессия с этим ключом отвергаются. Потеря ответа после сохранения проверена.
- Конкурирующие изменения используют единую версию. При различных операциях один запрос получает STALE_VERSION; после обновления свободный непересекающийся запрос можно повторить. Нет автоматического принятия изменившихся условий.
- Сессия демо — случайная временная capability в заголовке. Это изоляция синтетического сценария, не замена аутентификации реального клиента/владельца.
- Исчезновение памяти при перезапуске ожидаемо. Демо не предназначено для нескольких серверов или Vercel serverless. Синхронный CAS в одном процессе не доказывает надёжность распределённого хранилища.

## Воспроизведение

```sh
npm ci --ignore-scripts
npm run test:booking-demo
node scripts/verify-booking-demo.mjs
npm run build:booking-demo
BOOKING_DEMO_MODE=synthetic-only npm run dev:booking-demo
```

Сервер привязан только к `127.0.0.1:4187`; страница `/booking-demo.html`. Он не читает `.env` и не выполняет миграций. `BOOKING_DEMO_MODE` не включает публичный приём.

Для браузерной среды с установленными Chromium/WebKit: `npm run test:booking-demo:browser`. В CI добавлены отдельная сборка демо и эти сценарии. Workflow подготовлен, но не отправлен и не запущен на GitHub.

## Проверки и ограничения доказательства

Фактические логи находятся в `.qa/booking-demo-evidence/`: HTTP-цепочка, серверные тесты, общая регрессия, отдельная сборка и обнаружение браузерных сценариев. Обычная сборка и 4 теста Sites также выполнены.

Итог текущей ревизии: `npm test` — 155 пройдено из 156, один явный пропуск PostgreSQL; отдельный `test:booking-demo` — 26/26 (уже входят в 155, не прибавлять повторно). Sites — 4/4. Сборка основного приложения и отдельного демо успешны. Для имени этой ветки в `vercel.json` подготовлено отключение автоматического деплоя; конфигурация ещё не отправлена на сервер.

Браузерные сценарии подготовлены для Chromium desktop и WebKit mobile: основной путь/отказ при плохом источнике и повтор после потерянного ответа, всего 4 запуска. Их обнаружение проходит; сами сценарии не выполнены. Локальный Chromium завершился с `socket() failed: Operation not permitted`; облачный браузер получил `ERR_CONNECTION_REFUSED` при обращении к локальному серверу. Визуальная приёмка, отсутствие переполнения, реальный iPad и Safari не подтверждены. Снимков результата нет.

PostgreSQL-проверка существующего проекта явно пропущена: выделенный сервер и клиент не предоставлены. Успех SQLite/памяти не называется проверкой Neon/PostgreSQL. Восстановление после настоящего аварийного перезапуска и работа нескольких серверов не проверены.
